MCP

Keys

Let Claude work in this center as one of its users, doing only what both the key and the user's role allow. What it does is in the Activity log under their name. A key that only reads is the safest. If a key may have leaked, delete it or make a new one.

Using a key

Claude Code: add the listmonk MCP server with the key (a superadmin has the server's address):

claude mcp add --transport http listmonk-{{ $d.CenterSlug }} <the MCP server's address> \
  --header "Authorization: Bearer lmm_…"

claude.ai and the Claude apps: tick Usable from claude.ai on the user's key; they then add the listmonk connector under Customize → Connectors and sign in with Google, with the address they use here.{{ if not $d.Connector }} A superadmin has to set the connector up first.{{ end }}

At most {{ $d.PerMinute }} requests a minute per key. Keys, settings, profiles and sign-in can't be changed through Claude.

What it can do

Contacts' addresses, names and attributes. Unticked, Claude sees stand-ins instead. Used directly, outside Claude, a key gets the real data: give keys only to people who may see it. One per user. Their Claude uses it when they sign in to the connector: tick it only for someone who wants that.
