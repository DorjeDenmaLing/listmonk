MCP

Keys

For Claude (claude.ai, the Claude apps and Claude Code), through the listmonk MCP server. Each key belongs to one of the center's users: Claude works as them, and can do only what both the key's permissions and their role allow. What it changes is in the Activity log under their name, "via MCP key …", as if they'd done it, and the center's rules apply as they do in the admin: nobody who unsubscribed is re-subscribed, and nothing is sent without the center's postal address. Give a key only what its user wants Claude for; a key that only reads is the safest.

Unless Claude may see personal data is ticked, Claude sees stand-ins for contacts' addresses, names and attributes, and can't export them. A key usable from claude.ai works for its user when they sign in to the center's Claude connector with Google, with the e-mail address they sign in here with{{ if not $d.Connector }}, once a superadmin has set the connector up in the hub{{ end }}. Otherwise it's for Claude Code: its user gives it to their own Claude. If a key may have leaked, delete it or make a new one.

Using a key

Claude Code: add the listmonk MCP server with the key (the server's address is in its README, or ask a superadmin):

claude mcp add --transport http listmonk-{{ $d.CenterSlug }} <the MCP server's address> \
  --header "Authorization: Bearer lmm_…"

claude.ai and the Claude apps: tick usable from claude.ai on the user's key (one per user), then they connect the listmonk connector under Customize → Connectors and sign in with Google as the address they use here.

The MCP server reaches the center at {{ $d.MCPURL }}. Each key makes at most {{ $d.PerMinute }} requests a minute. Keys, secrets, settings, profiles and two-factor sign-in can't be changed with a key: they're done here.

What it can do
Only what the user wants Claude for. Sending (campaigns:send, tx:send) and deleting are the riskiest; Claude asks before it changes anything, but the key is what limits it.
Contacts' addresses, names and attributes, and exports of them. Unticked, Claude sees stand-ins (the same one for the same address), which is enough to count, compare and follow someone through, and can still be given an address to add or look up. The stand-ins are made by the MCP server, not by listmonk: someone using the key directly, not through the server, gets the real data, so keep such a key to those who may see it. For the user signed in to the listmonk connector on claude.ai or the Claude apps with Google, as the address they use here. One such key per user. Once the key is ticked, its user's Claude can use it at their next sign-in to the connector, without their saying so: tick it only for someone who wants it.
